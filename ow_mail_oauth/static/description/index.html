The idea

How it works.

OW Mail OAuth extends OW Mail — the personal mail client for the Odoo backend — with an OAuth 2.0 authentication type. It builds on Odoo's standard google_gmail and microsoft_outlook modules for token storage and refresh, and adds the XOAUTH2 handshake to OW Mail's IMAP and SMTP connections. Existing password accounts keep working unchanged.

🧭

Provider presets in the wizard.

Pick Gmail or Microsoft 365 in the Connect Mailbox wizard — servers are pre-filled and the browser goes straight to the provider's consent screen. After approval the connection is tested and your folders are loaded.

🔄

Automatic token refresh.

Access tokens are refreshed in the background — reading, sending, and the new-mail check keep working without re-authentication. A revoked token puts the account in a clear error state with a Reconnect button.

🔀

Convert existing accounts.

Switch an existing OW Mail account from password to OAuth on the account form — one click on Connect with Google / Microsoft.

🛡️

Secure by construction.

No mailbox passwords in Odoo. The callback verifies ownership and a signed state token before any token is stored, and each user can only ever connect their own accounts.

Getting started

One-time setup.

1 Register a (free) app with Google Cloud and/or Azure / Entra ID — the module's README walks you through every screen, including the exact redirect URLs and permissions.
2 Enter the Client ID and Client Secret in Settings → General Settings (the standard Gmail / Outlook credential fields).
3 Every user: OW Mail → Connect Mailbox → pick your provider → sign in on the consent screen. Done.

Requires OW Mail and an Odoo instance reachable over HTTPS. Google marks the Gmail scope as restricted: use "Internal" for your own Workspace domain, or complete Google's verification for public production use.

Beta status: the module is fully unit-tested, but the end-to-end OAuth flow depends on your provider app registration — feedback from real-world Gmail / Microsoft 365 tenants is welcome.
